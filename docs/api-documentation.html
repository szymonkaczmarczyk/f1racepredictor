Autoryzacja i ochrona

API nie ma kont ani kluczy: wszystkie endpointy są publiczne i tylko do odczytu, poza POST /api/predict (liczy predykcję, czasem zapisuje ją w historii trafności) i POST /api/sync (pobiera nowe dane i douczy model). Zamiast logowania serwer stosuje trzy zabezpieczenia:

MechanizmOpis
HostSerwer odpowiada tylko hostom z listy F1_TRUSTED_HOSTS (domyślnie 127.0.0.1,localhost). Inny host → 400, {"error": "Host 'evil.example' is not trusted."}.
Origin / Sec-Fetch-SiteŻądania POST z obcej strony są odrzucane (403, {"error": "cross-origin request blocked"}). Bez tych nagłówków (np. curl) żądanie przechodzi.
Rozmiar treściMaksymalnie 64 kB na żądanie, inaczej 413.

Wymagane nagłówki przy żądaniach z treścią:

NagłówekOpis
Content-Typeapplication/json dla POST /api/predict.

Przykład (curl):

curl https://<twoja-domena>/api/lineup

curl -H 'Content-Type: application/json' \
  -d '{"circuit_id":"sepang","weather":"dry","entries":[{"driver_id":"russell","grid":1}]}' \
  https://<twoja-domena>/api/predict

POST /api/sync można wyłączyć zmienną F1_SYNC_ENDPOINT=0 (tak jest w kontenerach Dockera) i ma odstęp co najmniej 60 sekund między wywołaniami.

Konwencje i błędy

ZasadaOpis
FormatWszystkie odpowiedzi to JSON w UTF-8 z nagłówkiem Cache-Control: no-store.
DatyDzień: YYYY-MM-DD. Chwila: ISO 8601 w UTC, np. 2026-10-04T07:00:00+00:00.
PrawdopodobieństwaLiczby od 0 do 1, zaokrąglone do czterech miejsc (0.7648 = 76,48%).
IdentyfikatoryTakie jak w Jolpica-F1 (dawne Ergast): kierowca russell, max_verstappen; zespół mercedes, red_bull; tor sepang, baku. Wyścig: {sezon}_{runda}, np. 2026_16.
SezonParametr season jest wszędzie opcjonalny; domyślnie najnowszy sezon w danych.
PozycjeNumery pól startowych i miejsc od 1. P1 w tekstach to pierwsze miejsce.

Każdy błąd ma ten sam kształt, jedno pole z opisem po angielsku:

{"error": "entry 1: grid must be 1-26"}
KodKiedy
400Błędne dane wejściowe (opis w error), treść, która nie jest obiektem JSON, albo niezaufany host.
403POST z obcej strony albo /api/sync wyłączony na tym serwerze.
404Nieznany tor, kierowca albo endpoint.
409Synchronizacja już trwa.
413Treść żądania większa niż 64 kB.
429Synchronizacja wywołana częściej niż raz na minutę.
500Błąd serwera ({"error": "internal error"}) albo nieudany krok synchronizacji. Szczegóły tylko w logu serwera.

POST /api/predict

POST/api/predict

Liczy predykcję wyścigu dla podanych pól startowych: szanse na wygraną, podium i punkty, ryzyko nieukończenia i oczekiwane miejsce każdego kierowcy (20 000 symulowanych wyścigów). Dla wyścigu już rozegranego liczy ją tak, jak wyglądałaby dzień przed nim.

Treść żądania (JSON)

ParametrWymaganyOpis
circuit_idtakTor, np. sepang.
entriestakTablica od 1 do 26 bolidów, najlepiej prosto z GET /api/lineup. Każdy element:
PoleZnaczenie
driver_idwymagane, znany kierowca, bez powtórzeń
constructor_idzespół; domyślnie ostatni zespół kierowcy
gridpole startowe 1–26; domyślnie kolejność w tablicy
quali_positionmiejsce w kwalifikacjach 1–26
quali_gap_pctstrata do pole w procentach, 0–20
weathernieJedna z weather_options: dry (domyślnie), cloudy, light_rain, mixed, heavy_rain.
seasonnieSezon; domyślnie najnowszy.
tyre_degradation / track_difficulty / laps / distance_kmnieNadpisanie wartości toru (skale 1–10, liczba okrążeń, dystans).
grid_sourcenieSkąd pochodzi grid (wartości jak source w /api/lineup). Gdy podany, a wyścig jest przed startem, predykcja trafia do historii trafności. Wartość what_if = grid zmieniony ręcznie, nigdy nie zapisywany.
base_sourceniePrzy what_if: źródło gridu przed zmianą. Dla expected i expected_practice liczy model przedkwalifikacyjny.

POST /api/sync

POST/api/sync

Pobiera najnowsze wyniki, kwalifikacje, pit stopy, treningi, przebieg wyścigów i statusy toru, przebudowuje cechy i douczy model, jeśli doszedł nowy wyścig. Trwa od kilkunastu sekund do kilku minut. Bez treści.

Przykład żądania

curl -X POST https://<twoja-domena>/api/sync

Odpowiedź — błędy

403  {"error": "sync runs on a schedule on this server"}
409  {"error": "a sync is already running"}
429  {"error": "synced less than a minute ago; try again shortly"}
500  {"error": "02_build_features.py failed (exit 1); see sync.log"}

Odpowiedź — sukces

{
  "success": true,
  "last_success_utc": "2026-10-01T11:28:34.409850+00:00",
  "seconds": 353.3,
  "new_races": 0,
  "results_through": "2026_15",
  "retrain": "none",
  "trained_through": "2026-09-26"
}

Znaczenie kluczy w odpowiedzi

KluczOpis
new_racesIle nowych wyścigów z wynikami doszło.
results_throughOstatni wyścig z wynikami w danych.
retrainnone — model bez zmian, quick — douczony na nowych danych, full — douczony z pełną walidacją.
trained_throughData ostatniego wyścigu w danych treningowych.

Aplikacja uruchamia tę samą synchronizację sama co 15 minut, gdy jest potrzebna (patrz README). W Dockerze robi to osobny kontener sync, a endpoint jest wyłączony.
